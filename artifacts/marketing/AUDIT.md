# v3 marketing audit — 2026-11-01

- Public releases: repository metadata and the [GitHub release list](https://github.com/Legends/otp-harbor/releases) identify desktop `v2.0.1` and Android `android-v2.0.1` as published. `packaging/windows-store/public-version.json` says Store 2.0.1. No v3 release tag or exact v3 patch version was found. Use “v3 in preparation,” never a v3 download link.
- Platform shipping: Windows Store MSIX, Linux DEB/portable GitHub assets, Android signed APK in separate GitHub releases. macOS build/support code exists, but it has no supported public release. iOS has none. The old README and `site/index.html` advertised macOS; both now state only Windows, Linux and Android.
- Themes: desktop uses `AvaloniaThemeService` and appearance settings; mobile exposes System, Light and Dark preferences. Android Debug has an opt-in `EnableMarketingCapture` compile flag; Release builds reject it. Genuine screenshots must be captured from the actual app in each theme.
- Existing image consumers: Pages and the root README use the reviewed v3 Windows campaign screenshot from `packaging/windows-store/screenshots/en-US/marketing/`; Pages also publishes Android campaign PNGs from `packaging/android/marketing/en-US/`. Fastlane uses separate Android screenshot images. Store assets, promotional composites and source captures are spread across `packaging/` and `fastlane/`; the obsolete `docs/images/` duplicates were removed.
- Existing pipeline: `scripts/assets/Capture-WindowsStoreScreenshot.ps1` captures the real Windows window; Android capture uses ADB. `scripts/testing/Windows/Clear-DesktopDevelopmentAccounts.ps1` and `Clear-AndroidDevelopmentAccounts.ps1` create encrypted snapshots before resetting Debug vaults. Desktop has Debug account-import activation; Android has a Debug broadcast receiver. Format-v3 `.otphicons` is accepted by `OtpHarborIconPackImporter`, even though `docs/security/ICON_PACK_IMPORT_CONTRACT.md` still describes format 1. Core account JSON is the same on desktop and Android.
- Distribution: `.github/workflows/pages.yml` assembles the static site from `site/` and copies legacy image paths. `.github/workflows/build-and-test.yml` publishes independent desktop/Android tags and unsigned Store submission inputs. Website validation is in `scripts/validation/Test-PublicWebsite.ps1`.
- Required migration: gather reviewed genuine Light/Dark captures from the 26-account fictional dataset; record their hashes; generate separate composites, lossless web derivatives and Windows-only Store PNGs from them; switch README, Pages and Store publication manifests to the canonical outputs; remove old asset references only after those new references pass validation. The current campaign’s graphics cannot be grandfathered into the strict fictional-only v3 policy.
- Legal/security review: the first demo-name set had real-world collisions and was retired. The revised 26 names returned no exact indexed web result in a preliminary search, but all names and original geometric marks remain trademark candidates pending formal human review; see `TRADEMARK_REVIEW.md`. Synthetic seeds use reserved example domains. Only Debug vaults may receive demo data. No public screenshot or Store upload is authorized until manual inspection confirms no real identities, QR secrets, notification text or third-party logos.
